## 2. 已探明的关键事实

### 2.1 SSIO 的 AI 网关**已经上线**（这是本方案的基石）

用 TaskManager 内置 key 只读探测（2026-10-14）：

```
GET http://120.53.9.81:8100/v1/ai/models        → 403 {"code":"SCOPE_DENIED","message":"APIKey 缺少所需 scope"}
GET http://120.53.9.81:8100/v1/ai/usage?app=... → 403 {"code":"SCOPE_DENIED"}
```

**403 而非 404** ⇒ 模块存在、路由已注册，只是内置 key 没有 `ai:read` / `ai:chat` scope。
**结论：不需要新建服务端，只需要在 SSIO 侧授权。**

### 2.2 网关契约（来自 Bigfish，已被另一个 AI 实现并验证）

来源：`E:\University\Bigfish\docs\SSIO-AI-PROXY-PROMPT.md`（交接 Prompt）与
`E:\University\Bigfish\packages\core\src\aiClient.ts`（客户端参考实现，145 行）

| 项 | 值 |
|---|---|
| 对话 | `POST /v1/ai/chat/completions`（scope `ai:chat`） |
| 用量 | `GET /v1/ai/usage`（scope `ai:read`，支持 `groupBy=day\|app\|model`、`detail=1`） |

## 4. 设计草案（待评审，未实现）

### 4.1 分层与文件

| 层 | 位置 | 职责 |
|---|---|---|
| 客户端 AI 模块 | 新增 `electron/ai/`（如 `gateway.ts`） | 读配置、拼请求、解析 SSE、错误归类；**不 import electron 的可测部分单独拆出** |
| IPC | `electron/ai/ipc.ts` 或并入现有注册点 | `ai:chat`（流式事件回推）、`ai:usage`、`ai:models` |
| 契约 | `electron/api-factory.ts` | 加 `ai.*` DTO（沿用「DTO 唯一出处」的既有约定） |
| 渲染层 | `src/components/`（对话框组件） | 只订阅状态；沿用大肥鱼「渲染层不做业务判断」 |
| 设置 | `src/pages/Settings.tsx` | 开关 + 模型选择 + 用量展示 |

网络必须走 `pickFetch()` 那条路（尊重系统代理），不要另起炉灶。

### 4.2 四层权限（**核心安全设计**）

`api-factory.ts` 的 IPC 面就是 tool 清单，按副作用分层放开：

| 层 | 示例 | 策略 |
|---|---|---|
| **L1 只读** | 「我今天有什么」「整理下待办」 | 直接放行，无副作用 |
| **L2 常规写入** | 「周五交高数作业」→ 建一条 | **执行前预览确认**（复用现有预览 UI） |
| **L3 破坏性** | 删课、删班级、批量修改 | **二次确认 + 可撤销** |
| **L4 改代码** | 「把这个 bug 修了」 | **不自动执行**，见 §5 |

要点：tool 定义要**白名单化**（显式列出可用能力），不要"把整个 IPC 面暴露给模型"——否则模型一次幻觉就能删数据。

### 4.3 对话形态

- 保留 `Ctrl+Shift+A` 呼出（入口不变，用户习惯不变）。
- 由「单条解析预览 + 保存」改为「对话区 + 可执行的变更建议卡片」。
- 沿用现有 `Modal` 与霓虹风格组件，避免新视觉语言。

### 4.4 隐私开关

- 默认状态待定（建议**默认关**，首次使用明确告知）。
- 关闭时：不发任何内容到 SSIO / DeepSeek，对话框给出明确说明。
- 发送前可做本地脱敏（学号、手机号等）——可选增强。

### 4.5 最小兜底能力（用户已确认保留）

删掉正则解析器后，断网/网关故障时**不能等于功能归零**。兜底形态建议：

> **一个裸输入框 + 手动选日期/课程/类型**（不做任何自然语言解析，约 20 行）。

即：断网时用户仍能记事，只是不能「一句话说完」。这与本项目 offline-first 的调性一致。

## 5. 「让 AI 自己修自己的 bug」——现实边界

**不能做的事**：运行时代码在 `app.asar` 里，改源码不会生效；让 AI 直接改生产代码**没有回滚手段**。

**本项目恰好已有可行机制**：

```
electron/updater/patchApply.ts      → 退出时替换 app.asar
electron/resources/patch-helper.cjs → 替换助手
scripts/release-one-click.js        → 构建 + 发版 + 推给全量用户
```

**因此现实形态是**：

> AI 定位问题 → 生成改动 → 落到文件 / 打成补丁 → **人审一眼** → 走现有发版通道。

这已经是「它自己找、自己改」，唯一区别是最后一道闸在人手里。
**建议：闸门不要去掉**，风险不在 AI 聪不聪明，而在出错后无法回滚。
